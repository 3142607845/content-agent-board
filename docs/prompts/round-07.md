# Round 07 — 阶段 4：创作维度差异化与看板交互打磨

## 我的提问（用户视角）

round 06 的多版模式只是「同一件事跑三次」，三份产物之间没有本质区别。本轮我提了三个可迭代点，让 AI 先评审再动手：

1. 改 Planner：同一选题定向生成差异化提纲，固定区分**深度分析版 / 故事化叙述版 / 科普入门版**，保证是维度差异而不是随机文本区别。
2. 批量模式顶部加全局进度条，格式如「批量 3 版：已完成 2/3，当前运行版本 3」。
3. 结果卡片支持折叠/展开，默认折叠，只展示运行状态。

## AI 的评审意见（三条都收下了，但各有一个坑）

- **功能 1 有架构冲突**：现有版本数是 2/3/4 下拉框，而固定变体恰好 3 个，两者对不上。给三个选项：
  - **方案 A**：锁死 3 版，去掉下拉框，tab 直接叫变体名。
  - **方案 B**：下拉框换成三个变体的勾选框，可只选 2 个。
  - **方案 C**：保留 2/3/4，第 4 版叫「自由发挥版」——不推荐，第 4 版必然和前面撞车。
- **功能 3 有反伤风险**：「全部默认折叠会毁掉最好的演示画面」。这个看板的核心卖点是 4 个 Agent 并行流式吐字，全折叠后屏幕上只有 4 个小圆点变色，录 demo 时没有视觉冲击力。
- **功能 2 最便宜**：数据现成（`tasks[].status`），但口径要分清，失败/中断不能混进「已完成」。

## 我的确认与决策过程

**版本数冲突**：选方案 A，锁死 3 版。理由是这样的表达最诚实——三个明确维度就该是三个固定选项，留个 2/4 的下拉框反而让人以为能随便加，加出来的第 4 版必然是前三个的重复。

**折叠的默认策略**：接受 AI 的建议，改成「默认折叠 → 节点开始运行时自动展开 → 跑完保持展开」。这样既满足我要的紧凑看板，又不会牺牲流式输出的可见性。

**差异化怎么写**：AI 提出一个关键判断——只在 prompt 里写「深度 / 故事 / 科普」这种形容词没用，模型还是会给三份长得差不多的提纲。必须把**结构骨架**写死。我采纳了，`lib/variants.ts` 里每个变体都给到 4 步段落推进 + 分镜要求 + 配图风格。

**改动范围**：先只改 Planner，下游 4 个 Agent 不动。提纲本身已经携带角度和结构，长文/脚本照着写就会自然分化。等实测差异不够再加，避免一次性动 6 个文件。

## 实现要点

- **`lib/variants.ts`（新增）**：三个变体的纯数据定义（`key` / `name` / `angle` / `promptBlock`）。前后端共用——前端取 `name` 做 tab 标签和说明卡，后端取 `promptBlock` 注入 system prompt。放独立文件是为了不让客户端组件 import 到 `lib/agents/base.ts` 里的服务端依赖。
- **变体注入路径**：`page.tsx` 请求带 `variant` → `POST /api/run` 用 `isVariantKey` 校验（非法值 400）→ `createRun(topic, variant)` 存入 `RunState.variant` → `runPlanner` 构造 `new PlannerAgent(run.variant)` → 构造函数把 `promptBlock` 追加到 system prompt。`variant` 是可选参数，不传时行为与改动前完全一致。
- **单节点重跑不受影响**：`rerunNode` 复用 `run.outline`，不需要重新跑策划，因此变体信息天然保留。
- **折叠实现**：`expanded: Partial<Record<NodeId, boolean>>`，默认全折叠；`node:start` 事件里调 `expandNode` 自动展开；折叠态给「首行预览 + 已生成 N 字」，配图卡折叠后保留缩略图；状态栏右侧加「全部展开 / 全部收起」。
- **进度条口径**：只把 `completed` 计入「已完成」，`failed` 与 `aborted` 各自单独计数并标红/标黄，不混进已完成。进度条宽度 = `completed / total`。

## 遇到的问题

1. **差异化可能失效**：如果只在 prompt 里加形容词，模型输出会高度同质。解决办法是把结构骨架写死（每版给 4 步段落推进、明确论据类型、明确配图风格），实测三版骨架完全不同才收工。
2. **折叠初版把页面撑长了**：第一版为了「展开后完整阅读」，把 `<pre>` 的 `max-h-80` 去掉了，结果一展开整页高度暴涨、滚轮滚动的是整个页面，滚动位置还会跳。我提出「希望是通过滚轮展开内容而不是整个页面移动」，恢复 `max-h-80`（策划卡 `max-h-64`）+ `overflow-auto`，改为内容区内部滚动。
3. **文档断档**：`round-06.md` 一直没写，阶段 3 的导出与批量模式没有决策记录。本轮补写，保持档案连续。

## 验收结果

### 三版提纲差异（同一选题「远程办公的利与弊」，实测策划输出）

| 变体 | 长文骨架 | 分镜特征 | 配图首条 |
|---|---|---|---|
| 深度分析版 | 矛盾现象切入 → 论点一/二/三（配斯坦福实验、微软协作数据等论据）→ 主动引入反面观点并回应 → 三条可执行建议 | 抛反直觉问题 → 层层递进 → 明确判断 | 极简信息图，左右分屏对比冷灰色调 |
| 故事化叙述版 | 2023年3月杭州产品经理林珊搬工位 → 第三周冲突爆发 → 尝试与犹豫 → 转变 → 一句短观点 | 前3秒手机闹钟字幕钩子 → 中段快切生活细节 → 转折 → 落点 | 清晨飘窗边写实生活摄影，家居服抱电脑 |
| 科普入门版 | 搬家类比 → 第一步/第二步/第三步（一次只讲一个变化）→ 三个新手误区 → 一句话收口 | 一个类比贯穿全片 → 分步骤 → 避坑提醒 | 极简扁平插画，餐桌一条虚线分两半 |

段落骨架、论据类型、配图风格三者同时分化，不是措辞差异。

| 验证项 | 结果 |

## 反思

本轮三个功能都来自「用起来别扭」的真实体验，而不是提前设计的清单：

- 多版跑三次出来一样 → 说明数量扩展没有意义，维度扩展才有。
- 整页滚动 → 说明「展开」的正确交互边界是内容区，不是页面。
- 全折叠看不到 AI 在干活 → 说明默认态要为「演示时刻」让路。

一个可复用的经验：**做差异化功能时，先问「差异体现在哪个字段上」**。答不出来，就只是随机性。
