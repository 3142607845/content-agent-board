# Round 06 — 阶段 3：看板形态收敛与批量能力

## 我的提问（用户视角）

阶段 2 跑通后，我想把看板做得更像「流水线」。本轮提了三件事：

1. 配图 24 小时就失效，图片能不能留在本地。
2. 用 React Flow 画节点画布，让节点之间的依赖关系更直观。
3. 内容要能导出，另外想要批量生成的形态（一次多个选题、一个选题多个版本）。

## AI 的方案

- **图片持久化**：Seedream 返回的 URL 带 `X-Tos-Expires=86400`，24 小时后失效。改为请求 `response_format: "b64_json"`，拿到 base64 后解码写入 `public/generated/{uuid}.png`，前端直接引用 `/generated/xxx.png`。
- **React Flow 画布**：策划节点在上、4 个内容节点在下，节点间连线表示依赖，节点内展示状态与内容预览，点击展开完整产出。
- **内容导出**：把长文、脚本、小红书、配图地址拼成一份 Markdown，前端用 Blob 下载。
- **批量能力**：顶部加模式切换（单次 / 批量选题 / 多版生成），批量模式用 tabs 承载多个任务，每个任务独立连一条 SSE，串行执行。

## 我的确认与决策过程

**关于 React Flow**，实现后我实测否决了，理由不是技术不可行，而是**表达是错的**：

- 4 个内容节点摆成 2×2，视觉上暗示了「长文 → 脚本 → 小红书 → 配图」的先后顺序，但实际它们是完全并行的。用画布反而误导了架构。
- 拖拽时画布平移会导致节点位置漂移甚至看不到（`panOnDrag` 默认开启，拖节点等于拖画布），改 `panOnDrag={false}`、固定节点尺寸、开始时 `resetView()` 只是缓解，没有解决「布局本身在说谎」。
- 卡片网格同样能表达「1 个上游 + 4 个并行下游」，而且更省空间。

**我的决策**：整体回退 React Flow。用 `git checkout HEAD -- app/page.tsx package.json package-lock.json` 恢复，再 `npm uninstall reactflow`，回到卡片布局。

**关于小红书模型**，实测小红书和配图出得明显比长文/脚本慢，看板上看起来像没同步启动。小红书从 `doubao-seed-2-1-pro-260915` 换成 `glm-5-3-flash-260828`，与长文/脚本保持同一速度量级。

## 遇到的三个问题

1. **配图临时链接 24 小时过期**：见上，改 base64 落地到 `public/generated/`。断网刷新页面，图片仍在，验证通过。
2. **React Flow 节点拖拽时消失**：根因是画布平移抢了拖拽事件，本质问题则是布局表达错误。最终不修，直接放弃。
3. **切换版本数后旧任务标签残留**：多版模式把版本数从 3 改成 2，下拉框值变了，但页面上仍有 3 个任务 tab，表现得像「切换没生效」。真正的原因是旧 `tasks` 状态没清。修复：切换版本数、切换模式时都清空 `tasks` 并重置 `activeTaskIndex`。

## 验收结果

| 验证项 | 结果 |
|---|---|
| 图片持久化 | 写入 `public/generated/`，断网刷新仍可见 |
| 内容导出 | 生成 Markdown，含长文/脚本/小红书/配图 |
| 复制反馈 | 复制成功后按钮变「已复制」并置灰，新运行或重跑后恢复 |
| 小红书速度对齐 | 三路文字节点完成时间接近 |
| 批量选题模式 | 多行输入最多 3 个，串行执行，tab 可切换查看 |
| 多版生成模式 | 同选题跑 N 次，tab 切换查看各版本 |
| 版本数切换 | 修复残留 tab 后，切换立即清空旧结果 |

## 反思

本轮的批量模式是**数量维度**的扩展（同一件事跑多次），跑出来的 N 个版本之间没有本质差异，只是模型每次措辞不同。这为 round 07 的「创作维度差异化」埋下伏笔。React Flow 的失败也说明一件事：**可视化形式必须诚实反映执行关系**，好看的布局不等于正确的布局。
