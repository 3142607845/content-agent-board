# Round 02 — 系统架构设计

## 我的提问

我要做一个"自媒体内容工厂"：用户输入一个选题，系统并行调用多个 AI Agent 分别产出公众号长文、短视频脚本、小红书文案和配图，最后在一个看板上展示。

设计上的考虑：
1. 编排层自己写还是用 LangGraph？我倾向自己写轻量的。
2. 前端看板用 React Flow，节点状态 pending/running/completed/failed。
3. 内容实时推送用 SSE，不用 WebSocket。
4. 4 个 Agent 的关系怎么设计？中断和单节点重跑怎么处理？

先别写代码，把整体架构讲清楚再实现。

## AI 首版方案

AI 给出的架构：4 个 Agent 完全并行、无依赖，都只读选题输入。用自研编排引擎（不用 LangGraph），React Flow 画节点，SSE 推送状态。

## 我的判断与追问

我质疑：4 个 Agent 完全独立、互不通信，这算不算"多Agent协同"？为什么不用 1 个 Agent 出 4 份内容？

同时提出：是否可以用不同模型跑不同 Agent（各平台用擅长的模型）。

## AI 修正

AI 认同：
- 4 个 Agent 比 1 个好：prompt 专注度高、并行速度快、容错、可单独重跑、演示效果好
- 不同模型分工是合理的加分点
- 但纯并行确实不算"协同"，建议加策划 Agent 做上游

## 最终决策

采用方案 A：加策划 Agent。

结构变为：选题 → 策划 Agent（拆解选题，生成 4 份平台提纲）→ 4 个内容 Agent 并行执行。

这样有真实的上下游依赖，体现"协同"主题。
