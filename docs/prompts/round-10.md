# Round 10 — 阶段 7：平台风格预设模板库

## 我的提问（用户视角）

反复测试时发现一个明显短板：网页生成的内容风格比较单一。公众号、短视频、小红书三个 Agent 的写作风格是硬编码在后端 prompt 里的，想换一种文风只能改代码、重启服务，用户既不能自定义，也不能保存和切换。

所以规划新增：**平台风格预设模板库**。前端按公众号 / 短视频 / 小红书三个渠道管理模板，内置几套默认模板，支持新建、编辑、删除、保存自定义模板；流水线运行时为每个下游内容 Agent 下拉选择模板，入参变成「策划提纲 + 风格模板」，并且和已有的差异化提纲自由组合。

## AI 的评审意见

需求成立，而且和上一轮的 `variant` 正好构成两个正交维度：`variant` 只影响策划提纲的结构骨架，风格模板只影响下游三个文本 Agent 的写法，两者互不干扰。同时提出三个必须先定下来的取舍：

1. 内置模板能不能直接改？直接改会让演示环境的默认文风被改坏且无法复位。
2. 自定义模板存哪里？localStorage 最省事，但换浏览器就丢，服务端也无法在创建 run 时解析模板内容。
3. 风格在哪选、何时生效？卡片内切换即时重跑会频繁触发模型调用，也打乱原有的重跑节奏。

另一个隐藏前提：历史回看读的是落盘快照。如果 run 里只存模板 id，模板被编辑或删除后，历史任务就说不清当时用的什么文风了。

## 我的确认与决策过程

| 决策点 | 选择 | 理由 |
|---|---|---|
| 内置模板权限 | 只读 + 复制为自定义 | 默认文风永远可用、可复位；想改就先复制一份 |
| 自定义模板存储 | 服务端 `data/styles.json` | 与历史快照同一套落盘思路，刷新/重启/换标签页都不丢，服务端可校验 |
| 选择位置与生效时机 | 控制台三个下拉，启动时快照 | 与「1 个选题 → 1 条流水线」的心智一致；回看可复现，运行中不会误触重跑 |

## 实现

**数据层**

- `lib/styles.ts`：`StyleChannel`、`StyleTemplate`、6 套内置模板（每渠道 2 套）、入参校验、风格块拼装。纯数据，前后端共用。
- `lib/style-store.ts`：自定义模板读写 `data/styles.json`；内置模板只读保护；创建 run 时把 `{ channel: templateId }` 解析成 `{ id, name, prompt }` 快照。
- 接口：`GET/POST /api/styles`、`PUT/DELETE /api/styles/[id]`。内置模板编辑/删除返回 403，同渠道重名返回 409，模板不存在或渠道不符在 `/api/run` 阶段返回 400。

**编排层**

- `createRun(topic, variant, batchId, styles)` 增加第四个参数，`RunState.styles` 存快照，随 `RunSnapshot` 一起下发与落盘。
- `buildSectionInput` 末尾追加风格块，并写明「与默认写作习惯冲突时以模板为准」。
- `AgentNodeState.style` 只存 `{ id, name }`，供卡片徽标、报告「文风」列、历史回看展示。
- 单节点重跑复用 `run.styles`，不重新解析模板。

**前端**

- header「风格模板 (N)」→ 三栏面板：公众号长文 / 短视频脚本 / 小红书笔记，支持新建、编辑、删除、复制；内置模板带「内置」标记且无编辑/删除入口。
- 控制台新增三个下拉，默认选中各渠道内置模板，另有「不使用模板」选项；运行中锁定。
- 卡片说明行显示「风格 · xxx」，执行报告新增「文风」列，历史回看横幅显示本次选用的文风。

## 验证

| 验证项 | 方法 | 结果 |
|---|---|---|
| 模板 CRUD | 直接调接口 | 新建 201、编辑生效、删除后自定义数归零 |
| 内置只读 | `PUT /api/styles/builtin-xhs-seeding` | 403 |
| 同渠道重名 | 连续创建同名模板 | 409 |
| 非法模板 | `POST /api/run` 传不存在的 id / 渠道不符 | 均 400，未触发模型调用 |
| 前端面板 | 浏览器实测 | 三栏 + 6 套内置模板可见；新建后下拉出现该选项；console 无 error |
| 端到端注入 | 建一套「每段开头写【STYLE-OK】」的长文模板，跑完整单次流水线 | 长文 10162 字，出现 26 处标记；`node.style`、`run.styles`、`report.nodes[].styleName` 均记录模板名；脚本/小红书未选模板时为空 |

测试产生的模板与 run 快照已全部清理，`data/styles.json` 恢复为空目录状态。

## 反思

- 「支持用户自定义」听起来像纯前端功能，但真正决定它能不能用起来的是**模板在什么时机被解析**。创建 run 时就解析成快照，既保证历史可解释，也让模板编辑不会悄悄改变正在跑的任务。
- 内置模板只读是一个小决定，但它避免了演示环境最常见的翻车：手一滑把默认文风改坏，评委看到的就是另一套东西。默认值应该始终可回到初始状态。
- 风格和提纲拆成两个正交维度后，组合空间从「3 种提纲」变成「3 种提纲 × N 套文风」，但没有增加任何编排复杂度——因为它们注入的是流水线的不同阶段。
